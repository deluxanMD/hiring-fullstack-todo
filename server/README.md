# Todo API (server)

REST API for the todo app, built with Express 5, TypeScript and MongoDB (Mongoose). Requests are validated with zod.

## Requirements

- Node.js 22 or later
- A MongoDB database (local instance or MongoDB Atlas)

## Setup

From the repository root, install dependencies for all workspaces:

```bash
npm install
```

Then create an environment file (see below) and start the server.

## Environment variables

The server loads a different file depending on `NODE_ENV`:

| Mode        | `NODE_ENV`    | File loaded | Started by    |
| ----------- | ------------- | ----------- | ------------- |
| Development | `development` | `.env.dev`  | `npm run dev` |
| Production  | `production`  | `.env`      | `npm start`   |

Both files live in the `server/` folder. They are git-ignored, so create them locally. `.env.example` is a committed template.

| Variable      | Required | Default | Description               |
| ------------- | -------- | ------- | ------------------------- |
| `PORT`        | No       | `4000`  | Port the API listens on   |
| `MONGODB_URI` | Yes      | none    | MongoDB connection string |

Example `.env.dev`:

```env
PORT=4000
MONGODB_URI=mongodb://127.0.0.1:27017/todo-dev
```

For MongoDB Atlas, use the `mongodb+srv://...` connection string from **Database > Connect > Drivers**, with your database user's password and a database name (for example `/todo`). Your IP address must be allowed under **Network Access**.

The variables are validated with zod at startup. If one is missing or invalid, the server prints the problem and exits.

## Scripts

Run from the `server/` folder, or from the root with `-w server`:

| Command         | Description                                          |
| --------------- | ---------------------------------------------------- |
| `npm run dev`   | Starts the API with `tsx watch` (reloads on changes) |
| `npm run build` | Compiles TypeScript to `dist/`                       |
| `npm start`     | Runs the compiled server in production mode          |

## Data model

A todo has the following fields. Timestamps are managed by Mongoose.

| Field         | Type      | Notes                           |
| ------------- | --------- | ------------------------------- |
| `_id`         | `string`  | Generated by MongoDB            |
| `title`       | `string`  | Required, trimmed               |
| `description` | `string`  | Optional, trimmed               |
| `done`        | `boolean` | Defaults to `false`             |
| `createdAt`   | `string`  | ISO date, set on creation       |
| `updatedAt`   | `string`  | ISO date, updated on every save |

## API reference

Base URL: `http://localhost:4000/api`. All request and response bodies are JSON.

### `GET /health`

Returns `200` with `{ "status": "ok" }`.

### `GET /todos`

Returns `200` with an array of todos, newest first.

### `POST /todos`

Creates a todo.

| Body field    | Type      | Rules                         |
| ------------- | --------- | ----------------------------- |
| `title`       | `string`  | Required, trimmed, not empty  |
| `description` | `string`  | Optional                      |
| `done`        | `boolean` | Optional, defaults to `false` |

```bash
curl -X POST http://localhost:4000/api/todos \
  -H "Content-Type: application/json" \
  -d '{"title": "Buy milk", "description": "2 litres"}'
```

Returns `201` with the created todo. Unknown fields are ignored.

### `PUT /todos/:id`

Updates a todo's title and description.

| Body field    | Type     | Rules                        |
| ------------- | -------- | ---------------------------- |
| `title`       | `string` | Required, trimmed, not empty |
| `description` | `string` | Optional                     |

If `description` is omitted, the existing value is kept. The `done` field cannot be changed here.

Returns `200` with the updated todo.

### `PATCH /todos/:id/done`

Toggles `done` (`true` becomes `false` and the other way round). No body is needed. The flip happens in a single database update, so simultaneous requests can't cancel each other out.

Returns `200` with the updated todo.

### `DELETE /todos/:id`

Deletes a todo. Returns `204` with no body.

### Errors

Errors are returned as JSON.

| Status | When                                                   | Body                                                               |
| ------ | ------------------------------------------------------ | ------------------------------------------------------------------ |
| `400`  | Invalid input, a malformed `:id`, or malformed JSON    | `{ "error": "Validation failed", "details": { "body": ["..."] } }` |
| `404`  | No todo with that id, or an unknown route              | `{ "error": "Todo not found" }` or `{ "error": "Not found" }`      |
| `500`  | Unexpected failure (for example, the database is down) | `{ "error": "Internal server error" }`                             |

The `:id` must be a 24-character hex ObjectId. Malformed JSON returns `400` with the parser's message in `error`.

## Try it with the REST Client

[`src/http/todos.http`](./src/http/todos.http) contains a request for every endpoint, ready to run with the VS Code [REST Client](https://marketplace.visualstudio.com/items?itemName=humao.rest-client) extension. Replace the sample id in the `PUT`, `PATCH` and `DELETE` requests with a real `_id` from `GET /todos`.

## Design notes

- **Validation.** Each route runs `validate(schema)` before its controller. The parsed result is stored on `res.locals.validated`, because `req.query` is read-only in Express 5.
- **Error handling.** Express 5 forwards rejected promises from async handlers to the error middleware, so controllers don't need `try/catch`. Zod errors become `400` responses, and unexpected errors are logged and returned as a generic `500`.
- **Not found.** Controllers return `404` themselves when an id is well-formed but doesn't exist.
- **Limits.** The server does not enforce maximum lengths on `title` or `description`. The client limits them to 100 and 500 characters.
